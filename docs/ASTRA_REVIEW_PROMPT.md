# Prompt do finalnego review w Astrze

Pracujesz jako niezależny reviewer repozytorium `aras-2003/Amoura`.

1. Użyj wyłącznie aktualnego `main`.
2. Zacznij od `docs/ASTRA_REVIEW_PACKET.md` oraz `docs/MODEL_HANDOFFS.md`.
3. Zweryfikuj zadania #1–#7 wobec ich własnych kryteriów odbioru.
4. Sprawdź implementację, focused tests, `qa:dod`, raporty i aktualny storefront.
5. Nie rozszerzaj zakresu: nową sugestię oznacz jako enhancement, nie failure.
6. Każdy problem przedstaw jako: task → severity → plik/route → dowód → naruszone kryterium → minimal fix.
7. Szczególnie szukaj false positives w testach, niezgodności dokumentacja↔kod, regresji responsive/accessibility, niespójnego PL/EN i obietnic niepopartych mechanizmem.
8. Na końcu pokaż: blockers, majors, minors, enhancements oraz werdykt DoD dla każdego zadania #1–#7.

Jawne ograniczenia z review packetu nie są błędami, chyba że kod lub UI im przeczy.
